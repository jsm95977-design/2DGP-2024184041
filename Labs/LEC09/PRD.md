# PRD — 소닉 애니메이션 뷰어

> 근거 문서: [PRE_PRD.md](PRE_PRD.md)
> 작업 브랜치: `1006`

## 1. 개요

`sonic-sprite.png` 스프라이트 시트에 들어 있는 소닉의 모든 동작을 차례대로 재생하는 pico2d 뷰어를 만든다.

| 항목       | 내용                                    |
| ---------- | --------------------------------------- |
| 개발 언어  | Python 3                                |
| 라이브러리 | pico2d                                  |
| 결과 파일  | `sonic_animation_viewer.py` (단일 파일) |
| 리소스     | `sonic-sprite.png`                      |
| 실행 위치  | `Labs/LEC09/` (리소스와 같은 폴더)      |

## 2. 기능 요구사항

| ID | 요구사항                                                                                                               |
| -- | ---------------------------------------------------------------------------------------------------------------------- |
| F1 | 스프라이트 시트의 모든 동작(아래 3장의 10개 줄)을 재생한다.                                                            |
| F2 | 동작 하나를 **5회** 반복 재생한다.                                                                                     |
| F3 | 5회 재생이 끝나면 **1초** 쉰 뒤 다음 동작으로 넘어간다. 쉬는 동안에는 그 동작의 마지막 프레임을 멈춘 채로 보여 준다. |
| F4 | 마지막 동작까지 끝나면 첫 동작부터 **무한 반복**한다.                                                                  |
| F5 | 화면 크기에 비해 잘 보이도록 스프라이트를 **4배 확대**해 그린다. 모든 동작은 화면 중앙에서 시작한다.                   |
| F6 | 창 닫기 버튼이나 `ESC` 키를 누르면 프로그램이 정상 종료된다.                                                           |
| F7 | 걷기·달리기처럼 **이동이 포함된 동작은 재생하면서 오른쪽으로 이동**한다. 동작마다 속도가 다르다.                       |
| F8 | 이동하다 화면 오른쪽 밖으로 완전히 나가면 **왼쪽 밖에서 다시 들어온다**.                                              |
| F9 | 휴식(1초) 중에는 이동을 멈춘다. 다음 동작은 다시 화면 중앙에서 시작한다.                                               |

### 비기능 요구사항

- 코드는 `sonic_animation_viewer.py` 한 파일에만 작성한다.
- 프레임 좌표는 코드 위쪽에 데이터(리스트)로 모아 두어, 좌표를 고칠 때 로직을 건드리지 않게 한다.
- 단계마다 실행 가능한 상태를 유지하고 커밋한다(5장).
- 커밋 메시지는 **한글**로 작성한다.

## 3. 스프라이트 시트 분석

- 크기: **399 × 525 px**, RGBA (배경 투명)
- 프레임 간격이 일정하지 않으므로, 균등 분할이 아니라 **프레임별 좌표**를 쓴다.
- pico2d의 `clip_draw(left, bottom, width, height, x, y, w, h)`는 이미지 **왼쪽 아래**가 원점이다. 아래 `bottom`은 이 기준으로 환산한 값이다.
- 맨 위 제목 글씨(“Classic Sonic Sprites”)와 맨 아래 제작자 표기·작은 캐릭터 줄은 동작이 아니므로 제외한다.

## 4. 설계

### 화면·출력

| 항목              | 값                                    |
| ----------------- | ------------------------------------- |
| 캔버스            | 800 × 600                             |
| 배경              | 흰색 (`clear_canvas()` 기본)          |
| 확대 배율 `SCALE` | 4 (가장 큰 프레임 40×45 → 160×180 px) |
| 그리는 위치       | x는 `x` 변수(시작값 중앙 400), y는 바닥선 `GROUND_Y` 기준 아래 정렬 |

### 시간

| 상수         | 값    | 의미                 |
| ------------ | ----- | -------------------- |
| `FRAME_TIME` | 0.1초 | 프레임 1장 표시 시간 |
| `REPEAT`     | 5     | 동작별 반복 횟수     |
| `REST_TIME`  | 1.0초 | 동작 사이 휴식       |

### 이동

이동 속도는 프레임(0.1초)마다 x가 늘어나는 화면 픽셀 수다. 0이면 제자리 동작이다.

| 동작      | 속도 (px/프레임) | 초당 이동 | 5회 재생 동안 이동 거리 |
| --------- | ---------------- | --------- | ----------------------- |
| 걷기      | 10               | 100 px    | 600 px                  |
| 가속      | 16               | 160 px    | 480 px                  |
| 볼 구르기 | 24               | 240 px    | 720 px                  |
| 달리기    | 24               | 240 px    | 720 px                  |
| 대시      | 32               | 320 px    | 960 px                  |

- 화면 밖 판정 여유 `MARGIN`은 가장 넓은 프레임의 절반(40 × 4 / 2 = 80 px)이다.
- `x > CANVAS_WIDTH + MARGIN`이면 `x = -MARGIN`으로 옮겨 왼쪽 밖에서 다시 들어오게 한다.
- 이동은 재생 상태에서만 하므로 휴식 중에는 자연스럽게 멈춘다.
- 다음 동작으로 넘어갈 때 `x = CENTER_X`로 되돌린다.

### 데이터 구조

```python
# (동작 이름, bottom, height, 이동 속도, [(left, width), ...])
ACTIONS = [
    ('idle', 447, 39, 0, [(1, 29), (31, 26), ...]),
    ('walk', 407, 39, 10, [(8, 26), (37, 27), ...]),
    ...
]
```

### 상태 흐름

```
[재생] action_index의 프레임을 0 → n-1 순서로 표시, 매 프레임 x += 속도
   │      x가 화면 오른쪽 밖으로 나가면 왼쪽 밖으로 이동
   │ 한 바퀴 끝 → loop_count += 1
   │ loop_count < 5 → 프레임 0부터 다시
   ▼ loop_count == 5
[휴식] 마지막 프레임 정지, 이동 정지, 1초 대기
   ▼
action_index = (action_index + 1) % len(ACTIONS), x = 중앙 → [재생]
```

메인 루프는 `handle_events()` → 상태 갱신 → `clear_canvas()` → `draw()` → `update_canvas()` → `delay(FRAME_TIME)` 순서로 돈다. 휴식은 `delay(1.0)` 한 번으로 막지 않고, 휴식용 카운터를 프레임 단위로 세서 그동안에도 종료 이벤트를 받을 수 있게 한다.
